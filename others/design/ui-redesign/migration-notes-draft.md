# 后续迁移约束草案

版本：UI-2026.10-v1；网页候选稿，用户尚未批准。本文用于检查设计是否丢失已有行为，尚不是开工授权或最终规范。

## 设计范围与入口

正式App当前只有登录与基础课程入口。B1业务组件已有独立验证入口，D后续负责把它们接到正式壳中。图册把两者统一展示，不能据此宣称正式导航已经完成。安全学习、助手和学习记录保留未开放状态，不出现虚构的学习进度、成绩、AI回答或监控告警。

student-courses保留学生独立身份；教师或管理员的角色切换只能显示服务端已授权身份。学生不得通过前端切换得到教师或管理身份。平台、学校、学院的组织导航按授权生成：平台三层、学校学院与专业、学院仅专业。无权操作的账号显示只读提示，不能把学院管理员变成同级管理员的管理者。

教师目录索引与教学班表格是新的视觉组织，仍分别使用目录和班级授权。列表只呈现接口返回的授权班级，不能展示未获授权班级的学生数据。搜索、归档筛选、目录分页、班级分页、清空目录筛选和“全部授权班级”均须保留。图中少量合成行不代表取消真实分页。

## 表单与权限

1. 新建课程与首班只有现有学院、教师、code、title字段；同时创建同名同代码目录与首班。已有目录开班通过catalog_id关联，不能增加重复目录输入。教师初次开课本人主讲；显式目录授权开班可指定同校其他教师，但不因此获得该班访问权。跨学院开班按现有学校管理员规则。
2. 目录代码不可在编辑中修改。修改名称、归档状态及管理员可变更负责人按原契约提交；存在活动班级不能直接归档目录，归档后可按原规则恢复。班级名称与加入/退出审批属于独立班级设置。
3. 新建学生必须保留学号与专业；已建立学生资料不能以空值清除。登录账号不可变更，独立于学号。教师和管理员保留可选学号、专业、性别、联系方式。选择学生与教职初始角色互斥；编辑资料与新增/撤销角色是独立提交，抽屉不得用单个保存按钮混淆。
4. 授权候选角色按管理员实际等级提供；学校管理员不能授予学校管理员。本人及更高管理账号按原canManageAccount规则只读。停用主讲账号前需交接；停用、重置撤销旧会话。首次改密为8–256位且不同于原密码；成功后撤销会话并返回重新登录。
5. 邀请分为账号开通邀请、班级邀请码，作用不同。账号邀请专业可不限定；保留使用上限、到期、有效/撤销/次数满/过期状态。班级邀请码支持有效期和重新生成，旧码立即失效；没有独立“启用/关闭加入码”接口。凭据仅在本次成功后显示，列表不回显原明文。
6. 班级名单保留搜索、状态、移出、退出历史与重新加入；精确账号拉入不开放外学院全量账号目录。协作教师可调整名单和审批；可查看教师关系，但不能更改授权、主讲、关键设置或归档。教师关系包含已移除与恢复协作，不能只显示当前有效教师。
7. 转交主讲后原主讲失去当前班级授权，应重新判权并返回可访问课程；历史关系保留。归档关闭当前学生资料访问、加入与修改，管理授权下保留历史名单与关系只读。图中额外确认框只是交互层保护，不改变服务端含义。

## 数据与操作状态

CSV分账号开通、班级名单两种上下文。保留UTF-8文件读取和文本编辑、模板下载、1MiB/500行限制、全量预检、错误行与字段、预检摘要和整批原子提交。编辑内容、学校、班级或类型变化后旧预检失效；密码不进入截图、日志或回执。响应丢失时保留原内容并复用同一幂等键重试，不能新建请求造成重复写入。

保留useBusinessQuery/useBusinessAction的会话检查、请求取消、搜索竞态隔离、pending禁重、ActionFeedback、同键重试和修订冲突处理。冲突后先重新读取，不静默覆盖别人修改；加载失败显示真实错误与重试。来源变化、退出、改密、重置、撤销权限后清理会话相关内存数据。
