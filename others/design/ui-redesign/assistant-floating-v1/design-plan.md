# 悬浮助手图片候选：设计计划与第一遍自查

版本 UI-ASSISTANT-2026.10-v1.1 · 2026-10-22 · 候选未批准。

## 任务依据

用户在本设计聊天逐轮确认：应用内悬浮；当前账号与设备的开关；录音后确认文字；收起停止音频；新对话跟当前班、已有对话固定范围；服务端文字历史至手动删除；吸边半胶囊；语音回答自动播报；四款外壳纯色。A登记提交 df29c4e0d73ecdefeafdbab47174926cc27e125b，设计分支 codex/ui-design-v1。原UI-v1只读。

## 第一遍：设计选择

- 外壳四色：经典白 #FFFFFF、青绿 #087F8C、蓝色 #2563EB、炭灰 #30363F。正文 #172B3A、次文字 #607482、分隔线 #DCE7EB、工作底色 #F5F8FA。色彩预设不改变整个产品的主题。
- 使用已批准、包内的 Noto Sans SC；正文15px，移动输入16px，标题16px/600，范围标签12px。手机小窗不把文字缩成10px来塞内容。
- 胶囊128×56，两侧各有44px点击区域，顶部窄拖动区；标题栏是展开面板的拖动区。静态稿中用原创编辑与波形图标，原参考PNG只作为外观依据，不作为发布资产复制。
- 网页/Windows面板420×560，正文左对齐；只有对话流滚动，标题/输入常驻。标题栏有历史、收起；更多动作归一个菜单，避免堆满小按钮。
- 手机小窗70%宽×43%可用高，使用短标题、展开和收起；正文展示短回复及引用，点输入展开全屏。全屏中提供完整历史、文字输入及录音确认。
- 处于课程页时，固定范围条显示教学班。历史列表每项显示标题、教学班和时间，不把不同课程消息混在一个对话流。
- 悬浮窗不加整页遮罩，页面仍可操作。设置、清空确认使用明确的内部对话区域，焦点与返回层级单独说明。

## 第二遍：对照需求修订

1. 不把原产品的实验室轻立体场景再塞进聊天窗口。辨识度来自已有课程背景、教学班范围与版本引用；助手本身保持用户选择的极简。
2. 原先手机90%宽方案被用户纠正。改为70%，保留1/4–1/3屏面积；输入自动全屏，让小窗留出页面操作空间。
3. 配色只作用胶囊、标题栏及外框，正文浅色；每款验证正文/图标对比，不用装饰渐变。
4. 吸边时先收成胶囊，再露出一半。露出的区域只负责恢复，不让截断的麦克风图标误启动录音。
5. 收起与关闭明确区分：收起可继续文字生成；关闭尽力取消请求。考试暂停使用完整状态说明，历史和旧回答不在后面透出。
6. 背景复用批准的静态课程画布，不预造新学习工作台。图册外标注合成数据、静态设计、系统框/键盘模拟，不能作为业务或原生验收证据。

后续：制作图册、截图、布局与状态交互检查，提交候选并等用户明确批准；批准前不冻结最终规范、不合并候选到A、不改产品代码。

## v1.1 图片修订：吸边再收进去一点

用户在图片审阅中回复“半隐藏可以更收进去一点”，这是一条修改意见，尚不是图片批准。胶囊总宽128px保持；吸边从隐藏64px/露64px改为隐藏80px/露48px，高56px保持。恢复区域仍有48×56px，满足44px最低触控要求；仅露出的把手恢复窗口，不直接触发文字或录音。左右侧、网页/Windows及手机使用同一几何规则，原48张画布和其余窗口交互维持范围。

第一遍选择48px而不是44px，给手势留少量余量；第二遍检查白色把手在浅色手机背景的边界和阴影，确保更收拢后仍可发现。补修改前后对照，重新验证左右可见宽度与恢复操作，再提交v1.1供用户审阅。
