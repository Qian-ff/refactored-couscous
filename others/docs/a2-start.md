## 新工作树登记

用户新建的 B/C/D 外部 Git 工作树分别绑定 `codex/b-core-a2`、`codex/c-content-ai-a2`、`codex/d-learning-ui-a2`。ownership.json 的 worktree=null 表示通过 Git worktree registry 按角色分支查找；本机路径由 workflow.py status 报告，不写死到公共契约。旧 task/core、task/content-ai、task/learning-ui 及其工作树原样保留，不再用于本轮开发。其他未指派的 detached 工作树也保留。

A 提交本轮协作工具与文档后在该提交创建本地固定标签 `a2-start`。A 将三个干净的新树快进同步到此标签，再检查分支、路径、所有权版本、contains_baseline 和 clean；全部一致才具备代码开工条件。共同起点的完整 SHA 用 `git rev-parse a2-start` 取得。此标签只表示准备基线，不能表示 A2 功能验收完成；后续公共契约升级另行发布完整 SHA。

环境按 [共用本机环境](shared-environment.md) 使用。主工作区保存配置和业务环境，新树直接复用；前端仅按需从共享缓存离线硬链接建立本地依赖。AI worker 当前未安装，等待 C 的实际引擎方案，不阻塞 D1 或 B 的账号课程工作。

## 交付顺序

1. B/C 先提出模型和接口需求，包含字段、权限、来源版本、迁移与依赖影响；A 维护公共模型衔接、迁移、后端挂载、OpenAPI 和生成客户端。新契约发布前，现有真实接口仍为 0.1.0，不先写假的搜索或考试接口。
2. D1 可以并行实现三角色不同首页、导航、兼任切换和响应式公共壳；现有账号/课程使用真实 API。后续功能显示等待接入状态。D 唯一编辑前端入口与公共路由，B/C 提交页面注册需求。
3. B 先交组织账号、课程授权与管理，再接 C 的已审核题目版本实现学习考试后端；C 先交授权内容、检索、审核发布和固定版本，再扩展问答与点击语音。D 依次接入真实内容和学习接口。
4. 中途契约与模块提交即可回 A 集成，不等三者全部做完才第一次协调。每次同步保留本地提交，在自己的分支合并 A 发布的 SHA，不重置工作树。
5. B/C/D 完成约定范围后，A 合并、联调、修复并做第二轮验收。

## A2 范围与验收

本轮覆盖三角色工作台、权限内课程/课件/题库搜索、教学管理与学习考核闭环，以及文字确认、带出处问答和语音播报。C 实现语音领域及界面，A 承担必要的原生录音桥接和麦克风权限接入；用户可配合授权设备。Windows 当前默认拒绝权限、Android 当前未声明录音权限、模拟器启动默认无音频，均须实际修改和实测后才能计为通过。

语音识别或云 API 未配置时如实显示状态；用户提供权限不等于模型和三端录音已经可用。完整监控由 E 扩展，正式安装器和签名由 F 扩展，不阻塞 A1 的既有验收。

A2 验收至少包括三平台乘三角色九种组合、学校/学院/课程授权与搜索隔离、生成草稿到审核/作答/服务端判分、历史版本、录音拒绝与允许、中文识别确认/问答出处/播报停止和离线失败反馈。包和页面必须对应本轮源码；更新通用入口，新增并实际使用 Open-A2.cmd，重新构建相关 Windows/安卓包。验收记录区别已实现、实测通过和外部阻塞。

每轮由各角色检查并提交本地 Git，A 验证后合并；仅当本轮 B/C/D 交付、三端集成及入口验收完成，才创建 checkpoint-2 并按既有授权推送 main 和里程碑，核对远端 SHA。准备基线阶段不额外推送。
