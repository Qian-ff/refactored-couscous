## UI v1 批准与冻结

1. 网页候选先供用户审阅；文件生成、自动渲染通过、工作树干净或沉默都不是批准。用户未批准时，设计支线只修订静态资料，A不合并候选，D/B/F不启动产品迁移，C/B2不启动新增功能。
2. 批准时A登记用户明确确认的图片版本、桌面提交SHA及确认记录。设计聊天随后补390px移动稿、视觉与组件/状态规范、已有功能映射、三端迁移约束和素材许可；显著偏离批准方向时再确认。
3. 移动稿和规范齐全后，设计聊天提交完整冻结SHA交A；桌面批准SHA与最终交接SHA分别记录。本次A已接收冻结包并发布D-UI基线，实施使用完整冻结规范，不能只用历史网页候选代替最终交接。
4. D牵头公共设计系统、产品壳、正式导航及已有功能接入；B修改所属教师/管理页面展示层，F配合原生适配，A协调具体文件交接和验收。跨所有权文件先由A明确唯一修改者，保持A–G原分工，不并行覆盖同一文件。

## 持续界面规则

凡新增或调整UI设计，必须使用frontend-design，先读取已批准的版本化规范，再提出颜色/字体/布局/主题方案并自查后实施。当前主色#087F8C、辅助蓝#2563EB、背景#F5F8FA、正文#172B3A及安研通品牌保持；实验室轻立体用于主题与关键视觉，业务表格和表单保持清晰。

本次专项的网页批准与规范冻结已完成，当前规范为[UI-2026.10-v1](../design/ui-redesign/design-spec.md)。以后常规新功能和新页面沿用冻结风格，自主设计、实现和截图自查，不逐页重复等待审美批准；明显改变风格、业务含义或权限时再确认。尚未批准的新方向继续保持候选状态，不能因本版已批准而自动批准其他改稿。

三端复用共享前端和真实业务规则；正式素材由责任角色迁入产品资源范围，运行和打包不依赖设计工作树。静态稿只用合成资料，不读取密钥/真实账号，不连接业务API，不替换请求、会话、授权或判分代码。尚未实现的题库、考试、助手、监控和新工作台继续显示真实未开放状态。
