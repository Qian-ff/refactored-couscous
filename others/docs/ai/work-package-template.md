# 协作工作包模板

责任角色或A主均可编制，先按[统一协作规范](../coordination.md)判断任务复杂度及是否需要A介入。已锁设计和规范用引用；按可一起实现、验证、交付的成果合并工作，不逐小步骤另建审批包。

## 普通局部任务

补齐以下实际值即可；身份、完整基线SHA、实际设置、所有权及依赖等开工事实按既有规则核验。A副即使处理小任务，也须注明main已提交的有效委托包编号和允许范围。

~~~text
/goal
编号与责任身份：
已获授权的目标、交付物：
修改范围、保留约束：
输入与依赖、完整基线SHA、开工条件：
实际检查命令、验收标准及证据位置：
自查：重大影响或未决事项；判断依据；是否具备开工条件。
合并后的里程碑与完成简报节点：
~~~

自查无重大未决事项且授权/阶段/范围允许时，用medium直接执行并自主续办，普通简报不等回执。全新模块首次Goal仍交用户手动复制启动；新模块/主要新增能力/重大变更才使用Plan＋grilling＋max，A主始终max。

## 复杂任务按需补充

在上面的Goal中补充真实thread ID/host及工作树/分支、实际设置核验证据、禁止范围、锁定的接口/数据流和兼容要求、分步操作及每步完成条件、异常与停止条件、最终接收对象。写清实际需要的内容，已有资料引用即可；无需预写全部实现。

## 需要A决定时

只交相关影响、实际证据、候选处理方式、需A决定的问题及原Goal引用。A给决定、必要修改和验收要求，原责任角色修订并自查后继续；新出现重大未决事项再补充，不重复送审同一份全文。

本地提交、三轮局部修复上限、系统临时目录handoff、main接收与阶段放行遵循统一规范。每次提交不单独触发汇报；自查和模板不扩大任何角色写权限、A副委托或推送/发布授权。
