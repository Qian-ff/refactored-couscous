# A：总控与架构任务书

请作为 SafeLabPlatform 的 A 角色工作。本任务以根 AGENTS.md、设计基线与真实接口契约为准，A1 的实际实现、验收状态与可交接基线见 others/docs/a1-handoff.md；后续模块按已发布基线继续开发。

## 开始前

1. 打开主工作区，确认当前分支为 main。
2. 读根 AGENTS.md、others/docs/design.md、others/contracts/README.md 和 ownership.json。
3. 先落实可运行骨架与契约，再允许依赖它的模块展开。

## A1：当前底座目标

1. 锁定技术骨架的来源提交、依赖和许可；接入可运行服务与前端。
2. 统一学校/学院/课程授权模型、初始迁移与真实 OpenAPI；生成三端接口类型。
3. 管理后端总入口、领域路由挂载、数据库迁移、部署和公共契约；A1 初始化前端入口后交给 D。
4. 验证真实 PostgreSQL、学校/学院/课程授权、共享网页、Windows 可搬移测试包及安卓模拟器运行，三端实际登录同一服务。完整语音与监控不属于 A1。
5. 修正工作区基线检查；发布已提交的基线 SHA、契约版本、验证证据及交接报告。准备脚本或仅构建成功不能替代运行验收。

## A2：后续集成

审查并合入 B–G 的独立提交，统一处理接口/迁移/客户端变更，验证教学与风险闭环并协调正式发布。完整语音由 C、监控由 E、原生权限与正式安装器由 F 实现；F 扩展现有壳工程。

## 修改范围

- *

范围以 ownership.json 为准。A 的全仓库权限用于底座和集成；模块交接后先明确修改交接，避免同时编辑。D 维护前端公共路由，A 维护后端入口、迁移、依赖和共享类型。

## 每轮交付

按根 AGENTS.md 检查并提交本轮文件到 main；回报 commit ID、可复现的验证命令/结果及未完成事项。无改动不建空提交。准备文件存在不代表功能已实现；以运行证据和 others/qa/acceptance.md 判断完成。客户端包不包含密钥、真实数据或源码路径依赖。
