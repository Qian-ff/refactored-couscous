# SafeLabPlatform 设计基线

版本：2026-10-21 / 用户已确认产品范围。A0 公共底座与阶段交接见 a0-handoff.md；A1 历史验收见 a1-handoff.md。以下设计要求不自动表示业务或三端功能已完成。

## 1. 目标、用户与取舍

软件品牌为“安研通”，英文名 LabConnect；正式全称“安研通——实验室安全智能协同管理平台”，窗口标题“安研通”，宣传语“让安全管理更智能，让实验协同更畅通。”。机器可读来源为 ../config/branding.json。外部参考材料的产品名称仅用于识别资料来源，不作为本项目品牌。

面向挑战杯与小规模试用，2 人配合多 AI 聊天，11 月尽早形成合格三端。预计实施 15–20 个工作日，工期受接口、模型与实机验证影响。

网页、Windows、安卓均有学生、教师和管理员入口，共用账号、权限和正式数据。专业范围为通用安全＋化学实验室。

教学闭环：授权资料 → AI 草稿 → 教师审核 → 关卡学习 → 分项考核 → 自动培训达标记录 → 复训。
风险闭环：视频/摄像头 → 本地疑似风险 → 教师确认 → 去身份案例草稿 → 审核发布 → 学生训练。

首版包括四项特色：AI 建题、找隐患/剧情闯关、点击语音助手、监控预警。积水、多路 IP 摄像头、完整 3D、真实门禁和校园统一认证留作后续扩展。

竞赛演示以真实流程为核心，已实现、实测和规划分开陈述，不虚构效果、使用人数或检测指标。私密参考 PPT 只作内部需求参考，不进入仓库、云模型或题库。

## 2. 技术与数据

共享前端采用 React/TypeScript/Vite/Tailwind/shadcn；Electron 打 Windows，Capacitor 打安卓。FastAPI/SQLModel/Alembic/PostgreSQL 提供共享业务。以 FastAPI 官方全栈模板为骨架参考，身份组织和教学逻辑专门实现。

源码目录固定为 web、desktop、android、others。客户端可分别发布，构建使用完整仓库共享资源；客户端安装后不依赖开发目录。后端与监控节点另行部署。

统一用 pnpm 管理前端；业务服务按模板核定的环境，AI 工作进程使用独立 Python 环境。框架接入时记录精确版本、提交和依赖锁。

本机先验收，准备同一套可迁云部署方式。业务服务可迁云，监控节点留在本机/校内，只向业务数据库上报计数、时间、状态和去身份摘要。首版不要求异地回看本地画面。

PostgreSQL 保存学校、账号、课程、题目版本、成绩、记录、配置元数据及任务。课件/课程图存授权文件区。监控媒体存本地节点。客户端只缓存界面资源和未提交草稿；联系不上服务端时不离线判分或发记录。

后台重型工作通过有进度的任务执行，状态为 queued/running/succeeded/failed/canceled；初始重型单任务、其他排队。GPU 或模型失败与普通业务隔离。

## 3. 组织和账号

学校为隔离租户，学院为组织范围，课程为具体授权对象。
- 平台运维：学校开通、总数据库、平台接口及系统运维。
- 学校管理员：本校组织/账号/课程、共享、跨学院协调、本校 AI。
- 学院管理员：一个或多个授权学院业务。
- 教师：被分配课程；实验室监控另外授权。
- 学生：本人记录及获准资源。

同校多管理员共用一套正式数据，按范围操作。跨学院选课只开放该课程必要资料、作答和成绩，不开放全学院档案；选课不授权监控。

学生字段：学校、独立学号、学院、专业、姓名、性别、联系方式。教师/管理员使用对应资料。性别和联系方式默认选填，学号按学校唯一且不等同于登录名。学生账号不能兼任教师或管理员；教师与管理员可以兼任。工作身份 student/teacher/administrator 由服务端验证 X-Work-Role，教师身份只使用教师权限，管理员可组合已获多学院范围。兼任账号默认教师；非法或撤销身份拒绝，不回退更大权限。账号停用、会话撤销及授权变更逐请求检查。

管理员导入或学校邀请码开通，学校＋账号＋密码登录，首次改密/重置密码。教师和管理员权限由上级授权。所有权限在服务端验证，不信任客户端提交的学校/角色字段。

内置演示账号密码约定为 `88888888`；自建学生、教师和管理员账号按既定开通方式创建并使用各自密码。演示配置和重置工具仅作用于固定样例账号，不限制新建账号或按角色统一覆盖自建密码。

## 4. 课程与变更

CourseCatalog/catalog_id 为课程目录，既有 Course/course_id 为教学班。目录和班分别保留代码、名称、学院/学校，旧班一对一回填目录，不按同名合并，旧 ID、选课、教师与接口保留。负责人管理目录及审核共享资源，不自动读所有班名单、考试或成绩；跨学院开班由学校管理员协调，普通教师保留创建本人目录和首班的能力。

每班一名主教师，可加协作及原子交接。学生与班多对多；默认邀请码自助加入/退出，可开启审批。协作教师可教学、发布任务、调整本班名单，主教师/有范围管理员负责教师授权、转交和归档。批量导入提供 CSV 模板及逐行预检，全部通过后事务内重新校验/提交，幂等不覆盖已有密码/授权。

有历史数据的课程归档；退课、换教师、停用账号保留历史、版本和审计。新教师按课程接手，旧授权移除后不再访问当前课程。

跨学院题库按范围分享，区分引用和复制修改。多人同时编辑进行版本检查，冲突要求核对，避免静默覆盖。

## 5. 课件、题库与考核

首版接收文字型 PDF/PPTX/DOCX/TXT 和输入知识点；扫描件或提取失败时提示补文字。文档内容是资料而非系统指令。

出题流程：提取来源 → 选题型/数量/难度 → AI 草稿 → 手动增删改/选题重生成/整组重生成 → 审核发布。包含知识点、答案、解析、页码/段落、审核人和版本。

题型：单选、多选、判断、情境选择；关卡另外支持热点和排序。已发布题目、试卷及评分规则保留快照，编辑不改变历史作答。

达标条件：必修关卡完成＋终测默认不少于 80 分＋教师标记关键题全对。服务端自动生成平台培训达标记录，默认有效 12 个月，可按课配置，历史保留。正式效力由学校确认，不自动控制门禁。

考试前不向学生返回答案。终测默认最多3次、时限60分钟，教师发布前可调整；多选全对才得分，否则0。展示最高成绩，达标须同一次同时满足分数与关键题，不跨次拼接。正式答案服务端保存并有版本，刷新/重登续接同次、不额外占次；关闭页不停时，超时按已保存答案交卷，断网未上传不算保存。练习即时反馈；终测关考后教师统一公布答案解析。幂等防重复占次/发记录，错题按知识点复训。

任一有效正式作答期间，暂停该学生账号跨班/会话/设备的全部平台AI辅导，其他账号不受影响；交卷/超时/合法中止后重算，有其他考试仍暂停。B2 提供真实状态，C在问答/续问/任务执行与返回均验证，状态不可核实暂停学生辅导。C阶段先以教师真实问答/语音验收，B2学生联合验收后接通。

初始样例：通识、化学各一门示范课程，共 6 个关卡、约 60 道待审核题。专业安全内容真实使用前需相应教师复核。

## 6. 学习与语音

关卡结构：短课 → 场景观察 → 找隐患/剧情选择 → 依据解释 → 反馈 → 复训。地图、徽章辅助进度，报告具体知识薄弱点。

语音：点击录音 → 确认识别文字 → 检索有权课件 → 回答带出处 → 中文播报。保留文字输入，支持停止录音/播放和继续提问；资料不足明确说明，原始录音处理后默认删除。

云AI由学校主动选择平台默认或本校完整地址/模型/密钥，未选择为未配置，不影响普通课程考试。当前开发用DeepSeek官方deepseek-flash，按已有额度限量实测，不能称为永久免费；Pro当前实际API名deepseek-v4-pro，正式学校自行配置，不硬编码。模型失败不静默换服务。本机HTTP推理先由A提供受控白名单再开放。

ASR采用独立Python3.13/sherpa-onnx1.13.8 CPU与锁定Paraformer模型；业务Python3.14分离，共用一份模型缓存。音频统一单声道16kHz PCM16 WAV，真实解码重采样，不改后缀冒充。播报先系统中文语音，拒绝/不支持真实反馈。worker示例识别不等于三端采集验证。

## 7. 监控、告警与案例

上传视频和一路实时设备摄像头均接入；采集端本地预览，授权端看实时采样和检测。初步按低频采样检测，模型吞吐与预览分别测量，避免积压过期帧。

优先实测人员拥挤及烟雾/火焰。人员按区域、核定人数和持续条件触发；烟火按连续帧确认和去重。候选模型和引擎的代码/权重许可分别记录，不能以引擎替代已验证烟火模型。

事件状态包含疑似、确认或排除、关闭。保留时间、证据、模型/规则版本和处理记录。原始监控不送云 AI，云端只解释去身份摘要。

教师确认事件后可转情境题/关卡草稿，使用摘要和原创示意图，不向学生发布原始画面；审核后发布。

## 9. 接口、安全与可迁移配置

学校主动选择平台默认或完整本校接口；未选时不自动继承。仅当前管理身份的学校管理员可设置本校AI，学院管理员不能更改学校接口。新地址必须完整本校密钥，不能继承平台密钥。测试→启用→新任务完整不可变快照，失败保留旧启用版，不混用地址模型密钥；三端只读掩码/状态和版本。

服务端 AES-GCM 加密敏感配置，主密钥独立保存；密码不可逆哈希，传输 HTTPS。前端只看掩码和 key_present 等状态，客户端不存数据库或模型服务密钥。

更换 API：输入 → 测试 → 启用 → 新任务生效；保留审计。数据库仅平台运维切换 PostgreSQL 同引擎：检查 → 暂停写 → 备份 → 导入 → 核对 → 切换 → 恢复写；失败回退旧库。

文件、后台任务和监控证据均验证学校和资源范围。日常数据库管理通过产品业务界面、备份与迁移工具完成。

## 11. 三角色工作台与搜索（新增要求，待后续模块实现）

网页、Windows、安卓均支持学生、教师、管理员三个工作台。身份决定首页导航与功能，设备决定布局和原生交互。D-UI先接已有功能的公共壳和导航；完整工作台、资料搜索及学习体验在C/B2真实接口交接后接续。B提供教师/管理页面，C/E提供所属页，D唯一注册HashRouter与公共路由。兼任切换经服务端确认，学生保持独立。移动五入口，教师管理触屏重排；未实现显示明确状态，不能只换通用页身份文字。

三种角色都要有课件搜索入口，三端使用同一搜索接口与权限规则。首版提供标题/文件名、课程与知识点关键词搜索；资料已成功提取文本时支持正文匹配与页码/段落定位。提供课程、文件类型、更新时间等合理筛选、分页与稳定排序。扫描件或未完成提取的资料说明检索能力，不伪造正文命中。基础关键词搜索不依赖云 AI 或收费 API。

搜索范围：学生只能检索本人有权访问的已发布课程课件和明确共享资源；教师检索本人授课/协作及获准共享资源；管理员按学校、学院授权范围检索和管理，管理身份不自动获得跨校资源。服务端必须先做权限筛选，再计数、分页和生成片段；建议词、结果总数、预览、下载及缓存同样不能泄露无权资源。学生搜索不返回教师答案、未发布草稿或考试受限资料。

结果展示课件名称、所属课程、类型、更新时间、可用的匹配片段及定位信息。三角色公共入口由 D 维护，C 实现课件检索后端与内容结果页，B 提供课程/选课和管理范围规则，A 发布真实迁移、OpenAPI 与共享客户端；F 验证原生端输入、键盘、返回和文件打开。

其他必要搜索随对应模块一起交付：B 实现有权限的课程、班级、学生/教师名单及培训记录查询；C 实现教师/管理员题库的关键词与知识点筛选；E 实现已授权实验室告警的日期、状态、类型查询。学生不因此获得全校账号目录、原始题库答案或监控权限。

搜索组件定义中文输入、查询/清空、加载、无结果、失败重试、未配置和无权限状态，旧请求不得覆盖新查询结果；退出或切换身份后清除前一身份的查询结果。精确接口字段由责任角色提交给 A 确认，未实现前保持设计状态，不预生成虚假接口或样例成功结果。
